## Fix-design review

### Task 2 — common-t0 LL + β threading

- Shifting `(leg_0_times, leg_1_times)` and each `sim_*_abs` to `t0=0` before BOTH `_nhpp_pointprocess_loglik` and `_hawkes_loglik_vectorized` is the correct fix: the Hawkes/NHPP LL is shift-invariant in the log-intensity term (depends only on inter-event differences) but the integral term `baseline·t_end` is NOT scale-invariant in absolute time. Scoring at the same `t0=0` origin the LS fit already uses removes the asymmetry. The fit ITSELF (`fit_hawkes_expkern`, `_fit_with_gofit`) already rescales internally, so only the SCORING origin needs alignment.
- The NHPP baseline (`_nhpp_baseline_per_sec`) is events/sec, origin-invariant; its integral uses the same `t_end` span, preserved by the shift. Confirmed consistent.
- `hawkes_decays: float | None = None` default None keeps free-β AIC for existing callers/tests (test_lr_test.py calls do not pass it) — back-compat preserved. When not None, pin the observed fit to it.
- A `not np.isfinite(lr_observed)` guard converts a silent NaN into a loud RuntimeError — appropriate.

It uses the same spectral-radius function the rest of the codebase trusts (Pitfall 6). Bounds unchanged. This is the §Kernel Forms `||α/β||<1` condition enforced at fit time, NOT a new gate boolean.
