## Implementation Decisions

### LL-failure diagnostic depth

- **Start with tick library scaling/init issue suspicion.** Real panel timestamps are absolute unix seconds (1.78e9 magnitude); tick's HawkesExpKern likelihood optimizer frequently blows up on un-rescaled timestamps. Hawkes fit landing at adjacency~1e-5 + baseline~1.7e-7 is consistent with optimizer collapse from numerical scale. Primary fix: rescale `block_timestamp - block_timestamp.min()` before tick consumes. Also re-examine decay=0.1 hardcoded prior (6-day window with ~10-min mean inter-event → decay=0.1/s decays in 10s → kernel can't see across events).
- **Hard time-box: 1 plan only.** Plan 04.1.1-01 = pre-reg-amendment + LL-fit-retry + (conditional scipy-fallback). No second diagnostic plan. If scaling fix succeeds, ship; if not, the SAME plan switches to scipy-MLE Fallback A.
- **Minimal telemetry: success/failure + final params in fit_report.json only.** Add `fit_report.json` field `why_not_likelihood: <string>` ONLY if LL still fails after rescale (i.e., scipy fallback fired). No `ll_diagnostic.json` audit-trail artifact, no per-step gradient log. Lean.
- **Synthetic-substrate regression check: REQUIRED.** New LL pipeline MUST recover η ≈ 0.5 on the **single-realization fixture** `analysis/tests/fixtures/synthetic_hawkes_eta_05.parquet` (from Plan 03-00 Wave 0; preserves η=0.5 ground truth). Tolerance: η_LL ∈ [0.45, 0.55] on this fixture. **CORRECTION (post-research):** `data/fits/ichi/0afc6af38e24/` is NOT a valid regression substrate — it is a 3-time-shifted stack that does NOT preserve branching ratio (its own profile-likelihood path gives η=0.052, not 0.5). The archived run stays as "LS-fallback evidence" but is NOT used for η-recovery validation.

### Acceptable resolution outcomes (AF-03 pre-registered)

- **η-coherence acceptance criterion: LL η ∈ [0.283, 0.371]** (= profile-likelihood CI from `ae9e3ba17900/fit_report.json :: branching_ratio_ci`). Pre-registered BEFORE 04.1.1-01 fit runs. If LL lands inside band → SHIP. If LL converges but outside band → NEEDS WORK (different basin; fix isn't real).
- **Fallback A (primary): scipy.optimize.minimize on `_hawkes_loglik_vectorized`.** We already trust the canonical-LL function (it's how the LR statistic is computed). If tick.HawkesExpKern remains broken, drop it entirely; replace with scipy BFGS/L-BFGS-B over (λ₀, α, β) on our own LL. Library-bug-isolated. Pre-registered as Fallback A.
- **Fallback B is NOT pre-registered** — if both tick LL and scipy on canonical LL fail, escalate to user (BLOCKER), do not silently promote profile-likelihood η or accept LS regularized. This forces honest investigation rather than method-shopping (AF-03 anti-fishing).
- **AF-03 pre-registration commit: amend `notes/PRE_REGISTRATION.md` with new section `## Phase 04.1.1 — LL-fit acceptance & fallback chain`.** Commit subject: `docs(pre-reg:04.1.1): lock LL-fit η-coherence band + scipy fallback`. Must commit BEFORE Plan 04.1.1-01 fit-retry runs — verifiable via git log temporal ordering.
- **Divergence handling: new LL fit is canonical; supersedes `ae9e3ba17900` LS run completely.** If new firing_condition differs from LS-fallback `null_lr` (e.g., gate_passes=true, or null_convex), real MLE wins. `ae9e3ba17900/` stays archived with one-line README pointer; new run_id is the v1.0 result; Phase 5 PDF cites the new firing_condition. The LS→LL divergence IS the methodology story for Phase 5 — explicit prose framing required.

## Specific Ideas

- **The fix is likely a one-line timestamp rescaling in `gofit.py`** — `events = events - events.min()` before passing to tick. The cost-side complexity is the test scaffolding (synthetic regression check) and the AF-03 pre-reg amendment, not the math itself.
- **scipy fallback is library-bug-isolated:** we already have `_hawkes_loglik_vectorized`; scipy.optimize.minimize over (λ₀, α, β) with positivity bounds is ~20 lines. If tick is genuinely broken at our scale, we sidestep it forever.
- **The LS→LL divergence is itself v1.0 evidence:** Phase 5 PDF should explicitly frame "LS-fitted Hawkes degenerates to NHPP by construction; canonical MLE recovers η=X. The pre-registered fallback chain (tick → scipy → BLOCKER) prevented us from silently shipping the LS artifact as a substantive null." This IS the methodology contribution.
- **Sample size n=778 is ABOVE the Q-9 identifiability floor of 300 events per leg.** So if LL fails again on the rescaled timestamps with scipy, the issue is NOT thinness — it's a deeper estimator pathology worth surfacing.
- **The `branching_ratio_ci` profile-likelihood path obviously works** — it produced η=0.341 with a tight CI on the same broken fit. This is independent evidence the substrate IS identifiable; only the joint-MLE optimizer is misbehaving.
