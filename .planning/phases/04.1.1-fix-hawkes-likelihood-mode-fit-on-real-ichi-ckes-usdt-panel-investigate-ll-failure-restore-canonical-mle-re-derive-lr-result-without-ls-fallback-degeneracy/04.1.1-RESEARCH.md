## Summary

The Phase 04.1 close-the-loop landed a real-data Phase 3 fit at `data/fits/ichi/ae9e3ba17900/` whose `hawkes_mv_params` are degenerate: `branching_ratio = 3.07e-4`, adjacency entries on the order of 1e-5, baseline on the order of 1.7e-7, `boundary_warning = true`, `fit_method_used = "least-squares"`. This is a fitting artifact of `tick.HawkesExpKern` falling back from `gofit="likelihood"` to `gofit="least-squares"` in `analysis/src/abrigo_x402/dgp/hawkes_fit.py :: _fit_at_decay`. The same panel's INDEPENDENT profile-likelihood path returns `eta_hat = 0.341` with CI [0.283, 0.371] — three orders of magnitude apart. The LS path is the broken estimator.

The proximate cause is high-confidence: tick's `ModelHawkesExpKernLogLik` C++ kernel raises `RuntimeError("The sum of the influence on someone cannot be negative")` during MLE init on Python 3.13 + numpy 2.x. The `except RuntimeError:` in `_fit_at_decay` swallows this and quietly degrades to LS. The hypothesis (HIGH confidence per CONTEXT.md `<specifics>`) is that absolute unix-second timestamps (`block_timestamp ∈ [1.78e9, 1.78e9]`, span only ~5.17e5 seconds) push tick's L-BFGS-B/AGD past numerical conditioning thresholds before iteration 0 completes. The literature confirms timestamp rescaling is the standard mitigation for Hawkes MLE on real-time data (arxiv.org/html/2405.10527v1, arxiv.org/pdf/2105.03800).

**Primary recommendation:** Rescale `events = events - events.min()` in `_fit_with_gofit` before the `learner.fit([leg_0, leg_1])` call. If tick LL still raises after rescale, swap the entire tick path for a scipy.optimize.L-BFGS-B fit over (λ₀ × 2, α 2×2, β scalar) with positivity bounds, wrapping the trusted `_hawkes_loglik_vectorized` from `lr_test.py` as the negated objective. Validate against synthetic substrate `0afc6af38e24` (η_true=0.5; reject if η_recovered ∉ [0.45, 0.55]). Pre-register the η-coherence acceptance band [0.283, 0.371] BEFORE the fit runs.

### Pattern 1: Timestamp rescaling at the tick boundary (PRIMARY FIX)

**What:** Subtract the panel-window start from event timestamps INSIDE `_fit_with_gofit` so the tick optimizer sees `events ∈ [0, ~5e5]` instead of `events ∈ [1.78e9, 1.78e9 + 5e5]`.

**When to use:** ALWAYS (before any `learner.fit([leg_0, leg_1])` call). The fit dict baseline / adjacency are scale-INVARIANT under additive shift (shift drops out of both `log(λ_i(t))` and `∫λ_i(t)dt`), so callers see no behavioral change in the returned baseline/adjacency.

**Example:**
```python
# Source: arxiv 2405.10527 §3.4 (standard mitigation); applied at analysis/src/abrigo_x402/dgp/hawkes_fit.py
def _fit_with_gofit(leg_0_times, leg_1_times, decays, gofit):
    # Rescale to t=0-origin to keep tick's C++ optimizer in a well-conditioned regime.
    # Hawkes LL is shift-invariant in absolute time: log(lambda) and integral both depend
    # only on inter-event differences. Returned baseline + adjacency are unchanged in value.
    t0 = float(min(leg_0_times.min(), leg_1_times.min()))
    leg_0_rs = (leg_0_times - t0).astype(np.float64)
    leg_1_rs = (leg_1_times - t0).astype(np.float64)
    learner = HawkesExpKern(decays=float(decays), gofit=gofit, penalty=_PENALTY,
                            solver="agd", max_iter=1000, tol=1e-7, verbose=False)
    learner.fit([leg_0_rs, leg_1_rs])
    return learner
```

### Pattern 2: Scipy fallback wrapping the canonical LL (PRE-REGISTERED FALLBACK A)

**What:** When tick LL still raises after rescale, swap the entire tick optimization for scipy.optimize.L-BFGS-B over the parameter vector `θ = (λ₀_0, λ₀_1, α_00, α_01, α_10, α_11)` with `decays` either fixed or treated as a 7th parameter, minimizing `-_hawkes_loglik_vectorized(...)`.

**When to use:** Inside `_fit_at_decay`'s `except RuntimeError:` branch. Replaces the current LS fallback completely.

**Example:**
```python
# Source: scipy v1.13 L-BFGS-B docs (docs.scipy.org/doc/scipy/reference/optimize.minimize-lbfgsb.html)
#         + abrigo_x402.dgp.lr_test._hawkes_loglik_vectorized (Pattern F canonical-LL)
import numpy as np
from scipy.optimize import minimize
from abrigo_x402.dgp.lr_test import _hawkes_loglik_vectorized
from abrigo_x402.dgp.hawkes_fit import compute_branching_ratio, _K_PARAMS, BOUNDARY_WARNING_TOLERANCE

def _fit_with_scipy_canonical_ll(leg_0_rs: np.ndarray, leg_1_rs: np.ndarray, decays: float) -> dict:
    """Library-bug-isolated MLE: scipy.L-BFGS-B over (lambda_0[2], alpha[2,2]) with fixed beta.

    Wraps _hawkes_loglik_vectorized (the same closed-form LL trusted by the LR statistic).
    Positivity enforced via per-parameter bounds (0, None); stationarity enforced post-fit
    via boundary_warning. Initial point seeded from the empirical rate to avoid the flat-
    likelihood region near the origin documented by stmorse.github.io/journal/Hawkes-python.
    """
    T = float(max(leg_0_rs.max(), leg_1_rs.max()))
    # Seed from empirical rate (Hawkes baseline ~ observed rate when alpha small).
    lam0_init = np.array([leg_0_rs.size / T, leg_1_rs.size / T], dtype=np.float64)
    alpha_init = np.full((2, 2), 0.01, dtype=np.float64)
    theta0 = np.concatenate([lam0_init, alpha_init.ravel()])  # shape (6,)

    def neg_ll(theta):
        lam0 = theta[:2]
        alpha = theta[2:].reshape(2, 2)
        ll = _hawkes_loglik_vectorized(lam0, alpha, decays, leg_0_rs, leg_1_rs)
        return -ll if np.isfinite(ll) else 1e18

    bounds = [(1e-12, None)] * 6  # strict positivity
    result = minimize(neg_ll, theta0, method="L-BFGS-B", bounds=bounds,
                      options={"maxiter": 1000, "ftol": 1e-9})
    if not result.success:
        raise RuntimeError(f"scipy L-BFGS-B failed: {result.message}")
    lam0_hat = result.x[:2]
    alpha_hat = result.x[2:].reshape(2, 2)
    ll_hat = -float(result.fun)
    eta = compute_branching_ratio(alpha_hat, decays)
    aic = 2.0 * _K_PARAMS - 2.0 * ll_hat
    return {
        "baseline": lam0_hat.tolist(),
        "adjacency": alpha_hat.tolist(),
        "decays": float(decays),
        "branching_ratio": float(eta),
        "loglik_in_sample": ll_hat,
        "aic": float(aic),
        "boundary_warning": bool(eta < BOUNDARY_WARNING_TOLERANCE or eta > 1.0 - BOUNDARY_WARNING_TOLERANCE),
        "fit_method_used": "scipy_canonical_ll",
    }
```

## Common Pitfalls

### Pitfall 1: Rescale before tick but NOT before downstream consumers
**What goes wrong:** If the rescale is applied INSIDE `_fit_with_gofit` (good — local scope), but a developer later "optimizes" by hoisting the rescale to `_extract_legs_from_panel`, the residuals.parquet's `rescaled_dt` column gets computed against the wrong wall-clock origin, breaking Phase 4 copula timing.
**Why it happens:** Premature DRY refactoring. The rescale is a numerical-conditioning hack for tick specifically, not a panel-wide normalization.
**How to avoid:** Comment the rescale as "tick-local; do NOT hoist". Add an integration test verifying `orchestrator.run_fit(panel) -> residuals.parquet.rescaled_dt` is unchanged before/after the fix.
**Warning signs:** Phase 4 cross-correlogram lag estimates shift after Phase 04.1.1 lands.

### Pitfall 2: Synthetic substrate η-recovery already broken at η ≈ 0.05 (NOT 0.5)
**What goes wrong:** The user's CONTEXT.md says "synthetic substrate `0afc6af38e24` ground-truth η=0.5" and demands `η_LL ∈ [0.45, 0.55]`. But inspection of `data/fits/ichi/0afc6af38e24/fit_report.json` shows: `hawkes_mv_params.branching_ratio = 1.63` (boundary warning, LS fallback fired), `branching_ratio_ci.eta_hat = 0.052` (profile-likelihood). The PROFILE-likelihood path itself does not recover η=0.5 on the synthetic. This raises a question about whether the synthetic fixture actually has η=0.5 in its true Hawkes-stacked simulation, or whether the panel-stacking method (3-time-shifted concatenation) breaks the simulator's branching ratio.
**Why it happens:** The synthetic substrate was a Phase 4 production-rep substrate (Plan 04-09), constructed by `data/raw/ichi/.../synthetic_p4_09_stacked_67000000_67002058.parquet` via time-shifted stacking. Time-shifted concatenation of three independent Hawkes realizations does NOT preserve the branching ratio — it creates segments of independent excitation separated by gaps. The "η=0.5 ground truth" claim is about the GENERATOR seed, not the realized panel.
**How to avoid:** Use `analysis/tests/fixtures/synthetic_hawkes_eta_05.parquet` (the 686-event single-realization Wave-0 synthetic fixture from Phase 3 plan 03-00, NOT the 3-stack derivative) for the regression test. This is the only known substrate where `synthetic_hawkes_eta_05_legs` fixture is keyed to η=0.5 ground truth.
**Warning signs:** Regression test fails on the 04-09 stacked substrate but passes on `synthetic_hawkes_eta_05_legs`.

### Pitfall 3: Decay β=0.1 incompatible with panel inter-arrival timescale
**What goes wrong:** The Hawkes exponential kernel φ(t) = α·β·exp(-β·t) at β=0.1/s decays to 1/e in 10 seconds. Real-panel mean inter-arrival is ~666s (517k seconds / 778 events). At β=0.1, the kernel has decayed to ~1.9e-29 by the next event on average — i.e., the model can never see across events, and the LL surface is dominated by the baseline term. The MLE is then effectively unidentified for α. This is a SECOND root-cause hypothesis (compounding the timestamp scaling issue): even with rescaled timestamps, tick may converge to a degenerate flat-LL basin.
**Why it happens:** β=0.1 was hand-picked from the DECAY_GRID `(0.01, 0.1, 1.0, 10.0)`. On a 30-day Phase 3 panel with mean inter-arrival ~666s, the AIC-min decay should be `β ≈ 1/666 ≈ 0.0015` — BELOW the entire grid. The grid's left edge (0.01) decays in 100s, still 6× faster than mean inter-arrival.
**How to avoid:** Either (a) extend DECAY_GRID to include `0.001` and `0.0001`, OR (b) let scipy fallback fit β as a free 7th parameter with bounds `(1e-6, 10.0)`. CONTEXT.md flags this as Claude's Discretion within scope.

**Warning signs:** η-coherence acceptance fails (LL η < 0.283 or > 0.371) on real panel with single-start scipy; multistart may resolve.

### Verified pattern: canonical Hawkes LL (lr_test.py L60-107)
```python
# Source: analysis/src/abrigo_x402/dgp/lr_test.py L60-107 (HIGH confidence, repo-verified)
def _hawkes_loglik_vectorized(baseline, adjacency, decays, leg_0, leg_1):
    legs = [leg_0, leg_1]
    if any(arr.size == 0 for arr in legs):
        return float("-inf")
    t_end = float(max(leg_0.max(), leg_1.max()))
    log_intensity_sum = 0.0
    for i, leg_i in enumerate(legs):
        lam = np.full(leg_i.size, float(baseline[i]), dtype=np.float64)
        for j, leg_j in enumerate(legs):
            a_ij = float(adjacency[i, j])
            if a_ij == 0.0 or leg_j.size == 0:
                continue
            dt = leg_i[:, None] - leg_j[None, :]
            mask = dt > 0.0
            dt_pos = np.where(mask, dt, 0.0)
            contrib = np.where(mask, np.exp(-decays * dt_pos), 0.0)
            lam += a_ij * contrib.sum(axis=1)
        if np.any(lam <= 0.0):
            return float("-inf")
        log_intensity_sum += float(np.log(lam).sum())
    integral = 0.0
    for i in range(2):
        integral += float(baseline[i]) * t_end
        for j in range(2):
            a_ij = float(adjacency[i, j])
            if a_ij == 0.0 or legs[j].size == 0:
                continue
            hist = legs[j][legs[j] < t_end]
            integral += a_ij * float(np.sum(1.0 - np.exp(-decays * (t_end - hist)))) / decays
    return float(log_intensity_sum - integral)
```

## Open Questions

1. **Will the timestamp rescale alone fix tick?**
   - What we know: tick's C++ kernel raises `RuntimeError("The sum of the influence on someone cannot be negative")` per the `_fit_at_decay` docstring. The literature confirms unix-second timestamps cause numerical-conditioning failures in Hawkes MLE (arxiv 2405.10527, 2105.03800).
   - What's unclear: Whether the failure mode is purely about absolute magnitude, or also involves the inter-event timescale × decay-grid mismatch.    - Recommendation: Build the scipy fallback FIRST (it's the load-bearing always-works path). Apply timestamp rescale as the cheap-add. Pre-register the chain so AF-03 is honored either way.

2. **Should decay β be freed as MLE parameter or extended in grid?**
   - What we know: Real-panel mean inter-arrival ~666s; β=0.1 decays in 10s. Grid is currently `(0.01, 0.1, 1.0, 10.0)`.
   - What's unclear: Whether freeing β destabilizes the L-BFGS-B convergence (Hawkes LL is known flat in β near optimum). Grid-extension is conservative and keeps the optimization in 6-D not 7-D.
   - Recommendation: Extend DECAY_GRID to `(0.0001, 0.001, 0.01, 0.1, 1.0, 10.0)` and AIC-min select — preserves existing architecture, adds 2 grid points. Free-β is v2.0 if AIC-min still picks the smallest grid value.

3. **Does the new Hawkes MLE pass the four-criterion gate or not?**
   - What we know: LS-degenerate `gate_passes=false` because `lr_rejects=false` (p=0.58) AND `ks_held_out_passes=false` (p < 1e-200) AND `eta_floor_met=false` (η=0.0003 < 0.2). All four failed on the broken fit.
   - What's unclear: With genuine MLE recovering η ~0.34, the eta_floor_met flips TRUE. The LR p-value will RECOMPUTE under new Hawkes adjacency; if Hawkes LL improves materially over NHPP, p_value drops. KS held-out test re-runs with new parameters; may or may not flip. Whether the gate passes is the headline scientific question this phase resolves.
   - Recommendation: Plan 04.1.1-03 verification append must NOT pre-commit to either outcome (`gate_passes=true` or `=false`). Document whichever lands. Frame divergence from 04.1-03 `null_lr` as the load-bearing methodology story per CONTEXT.md `<decisions>` divergence policy.
