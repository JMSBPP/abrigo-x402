## Tasks

### Task 1 — TS driver script `scripts/build_panel_real.ts`

Single one-shot driver that orchestrates the three bulk pulls and emits JSONL sidecars under `data/raw/ichi/0x61Ef.../`:

1. **Pool-event pull** (Blockscout v1 `getLogsV1`):
   - Loop over the block window in chunks of ≤ 100,000 blocks (well under the 1000-record cap given measured ≈30 swaps/day + 4-5 Transfer companions per swap tx = ~150-200 events/day → ~15k-20k events per 100k-block chunk = safe).
   - For each chunk: pull all logs emitted by the pool address. This captures Swap + Mint + Burn.
   - Decode using existing `fetch/src/decoders/uniswap-v3-swap.ts` (extend for Mint/Burn if needed).
   - Write JSONL to `data/raw/ichi/0x61Ef.../pool_events.jsonl`, one log per line.
   - Cost-ledger row per Blockscout call: endpoint=`blockscout`, paid_real=false, query_cost=0.

2. **Transfer-companion pull** (per unique tx from Task 1.1):
   - For each unique `transactionHash` from the pool-event JSONL: call Blockscout v2 `/transactions/{hash}/logs` to pull every log in that tx.
   - Filter to `topic0 == Transfer` (`0xddf252ad…`).
   - Append to `data/raw/ichi/0x61Ef.../tx_logs.jsonl` (one log per line).
   - Cost-ledger row per call.

3. **Vault-state pull** (Forno multicall):
   - Identify unique block numbers from the Swap events.
   - Call `snapVaultState` from `fetch/src/vault/state-snap.ts` over those blocks (batches of ~50 per multicall).
   - Write JSONL to `data/raw/ichi/0x61Ef.../vault_state.jsonl`.
   - Cost-ledger row per multicall: endpoint=`forno`, paid_real=false.

4. **FX-snap pull** (Forno raw readContract per block):
   - Call `snapFxBlocks` from `fetch/src/mento/historical-rate.ts` over the same unique blocks.
   - Write JSONL to `data/raw/ichi/0x61Ef.../fx_snap.jsonl`.
   - Cost-ledger row per call.

Provide simple progress logging to stdout (`[N/total] block-range chunk done`, `[N/total] vault state block done`, etc.).

Handle rate-limits with a small constant delay (50-100ms) between calls; on 429 back off 1-2s and retry up to 3 times.

### Task 2 — Python materialization

Add a small `analysis/src/abrigo_x402/cli.py` (or extend an existing entry-point) with a `materialize` subcommand:
- Inputs: the four JSONL files written by Task 1.
- Calls `panel.build_panel(events_jsonl, vault_state_jsonl, fx_snap_jsonl, tx_logs_jsonl)` to produce a polars DataFrame.
- Writes Parquet via `panel.write_panel(df, output_path)` with provenance metadata.
- Output path: `data/raw/ichi/0x61Ef8708fc240DC7f9F2c0d81c3124Df2fd8829F/{start_block}_{end_block}.parquet`.

If `panel.build_panel` does not yet accept a `tx_logs_jsonl` parameter (it was wired only for events from Plan 02-08), extend it minimally to merge Transfer rows from tx_logs into the events stream BEFORE the phantom-filter step. Document the extension in the SUMMARY.

## Rollback / re-runnability

The driver is idempotent: re-running overwrites the JSONL + Parquet outputs. The cost-ledger is append-only; re-runs will create duplicate cost rows. To clean re-run: `rm data/raw/ichi/0x61Ef…829F/*.jsonl data/raw/ichi/0x61Ef…829F/*.parquet` (do NOT touch cost-ledger).
